6.1.1 · Big-M арга гэж юу вэ?

Max ба Min — тэс өөр логик

Max бодлого «Байгаа нөөцөөрөө хамгийн их ашгийг хэрхэн олох вэ?» гэж асуудаг бол Min бодлого «Өгөгдсөн шаардлагыг хамгийн бага зардлаар хэрхэн хангах вэ?» гэсэн асуулт руу чиглэдэг.

Гол асуудал

Min бодлогод ≥ хязгаарлалт орж ирдэг тул түүнийг энгийн симплекс аргаар шууд бодох боломжгүй. Ийм бодлогыг M-арга (Big-M Method) буюу их торгуулийн аргаар боддог.

6.1.3 · Яагаад Big-M нэр өгсөн вэ?

«M» бол торгууль

«M» гэдэг нэр нь торгуулийн хэмжээг илэрхийлэх маш том тооноос гаралтай. Практикт M-ийг бодлогын бусад бүх коэффициентээс хэдэн зуу, хэдэн мянга дахин том байхаар сонгодог.

Санах зүйрлэл

Яг л мөнгөн торгууль хүлээсэн хүн түүнээсээ аль болох хурдан ангижрахыг хичээдэгтэй адил — алгоритм өөрөө Aᵢ хувьсагчийг аль болох хурдан 0 болгохыг автоматаар эрмэлздэг.

Зорилгын функцэд

Aᵢ нь +M (Min) эсвэл −M (Max) коэффициенттэй орно

Тиймээс Aᵢ-г эерэг утгатай (0-ээс их) орхих нь симплекс алгоритмын хувьд маш ашиггүй, маш өндөр өртөгтэй сонголт болно.

≤ → +S  ·  = → +A

a₁x₁ + a₂x₂ ≤ b  →  a₁x₁ + a₂x₂ + s = b  (s ≥ 0)
a₁x₁ + a₂x₂ = b  →  a₁x₁ + a₂x₂ + A = b  (A ≥ 0)
Жишээ: 4x₁ + 2x₂ ≤ 100 → 4x₁ + 2x₂ + s₁ = 100  ·  3x₁ + 2x₂ = 15 → 3x₁ + 2x₂ + A = 15
≤ · Нэмэлт хувьсагч

«s» бол ашиглагдаагүй үлдэгдэл

Компьютер тэнцэтгэл бишийг ойлгодоггүй тул түүнийг тэгшитгэл болгоно. Тэнцэтгэл бишийг тэгшитгэл болгоход s ≥ 0 гэсэн нөхцөл дагалдана.

6.2.3 · ≥ хязгаарлалт → −S + A

Бүлэг 6-гийн гол алгебр

Алхам 1. Илүүдэл хувьсагчийг хасна:
a₁x₁ + a₂x₂ ≥ b  →  a₁x₁ + a₂x₂ − s = b
Алхам 2. Зохиомол хувьсагч нэмнэ:
a₁x₁ + a₂x₂ − s + A = b  (s, A ≥ 0)
Жишээ: 2x₁ + 3x₂ ≥ 12  →  2x₁ + 3x₂ − s + A = 12
Яагаад Алхам 2 зайлшгүй хэрэгтэй вэ?

Симплекс алгоритм эхлэхэд суурь хувьсагчийн утга сөрөг биш байх ёстой. Гэвч x₁ = x₂ = 0 үед −s = b > 0 болох тул s = −b < 0 буюу сөрөг гарна — энэ нь боломжгүй. Иймд «s»-ийг шууд суурь болгож эхлэх боломжгүй.

6.3.1 ба 6.3.2 · Хоёр бодит хувьсагч

Үлдэгдэл ба давалт

+S · Нэмэлт хувьсагч (Slack)

Боломжит нөөцийн дээд хязгаар буюу ≤ хязгаарлалтад нэмэгдэж ордог.
2x₁ + 3x₂ + S = 100

Менежерийн өнцгөөс

S > 0 гарвал тухайн нөөц бүрэн ашиглагдаж дуусаагүй. Хязгаарлагч хүчин зүйл (Bottleneck) биш тул нэмж худалдан авах шаардлагагүй — сүүдрийн үнэ нь 0.

Жишээ: 100 цагийн фонд байснаас 80 цагт багтаан гүйцэтгэвэл S = 20 цаг — сул үлдсэн нөөц.

−S · Илүүдэл хувьсагч (Surplus)

Заавал биелүүлэх доод хязгаар буюу ≥ хязгаарлалтаас хасагдаж ордог.
x₁ + x₂ − S = 40

Менежерийн өнцгөөс

S > 0 гарвал байгууллага тавигдсан доод стандартыг давуулан биелүүлсэн. Энэ нь муу зүйл биш.

Жишээ: тэжээлд доод тал нь 40 г уураг шаардсан ч 45 г болбол S = 5 г — стандартаас давсан илүүдэл.

6.3.3 · Зохиомол хувьсагч (+A)

«Жинхэнэ» хувьсагч биш

≥ эсвэл = хязгаарлалттай үед эхний шийдийг олохын тулд албадан нэмдэг: x₁ + x₂ − S + A = 40. Практикт ямар ч бодит утга агуулдаггүй — энэ бол зөвхөн симплекс алгоритмыг эхлүүлэх математикийн хэрэглүүр.

Менежерийн өнцгөөс

Симплекс арга анх хаанаас эхлэхээ мэддэггүй тул зохиомол нөөцөөр стандартыг түр хангадаг. Гэхдээ энэ нөөц маш өндөр өртөгтэй (Big-M торгуультай) учраас менежер аль болох хурдан зохиомол аргаас салж, бодит бүтээгдэхүүнээрээ шаардлагыг хангахыг эрмэлздэг.

✗Сөрөг үр дагавар: бодолт дуусахад A > 0 хэвээр үлдвэл эдийн засгийн маш ноцтой асуудал үүснэ
Хатуу онош

«Компани өөрийн бодит нөөцөөрөө энэ зорилтод хүрч чадахгүй, систем шийдгүй байдалд оржээ (Infeasible)».

Иймд оновчтой шийдэд A = 0 байх ёстой — Big-M аргын бүх торгуулийн систем яг үүний төлөө ажилладаг.

6.4.1–6.4.2 · 6.4.4 · M-ийн үнэ цэнэ

Яагаад маш том тоо вэ?

Зохиомол хувьсагчид зорилгын функцэд маш өндөр торгууль тавьснаар симплекс алгоритм ашгаа өсгөх (эсвэл зардлаа бууруулах) гэсэн байгалийн зорилгынхоо дагуу A-г автоматаар 0 болгохыг эрмэлздэг.

Дүрэм

M нь бодлогын аль ч коэффициентээс хамаагүй том байх ёстой — эс тэгвээс алгоритм Aᵢ-г бүрэн хөөж чадахгүй байж болзошгүй.

Математикийн хувьд

M → ∞ (хязгааргүй том тоо).

Практикт

1 000, 10 000, 100 000 гэх мэт, бусад бүх коэффициентээс мэдэгдэхүйц том тоо (Excel Solver ийм тоог автоматаар оноодог).

6.4.3 · Max ба Min бодлогод M-ийн тэмдэг

Тэмдэг нь эсрэг байна

Min бодлого

+M·A (эерэг тэмдэг)

Зардлыг минимумчлах гэж байгаа тул A > 0 бол нийт зардал +M·A-гаар асар ихээр өснө. Тиймээс алгоритм A-г 0 болгохыг эрмэлзэнэ.
Z = 5x₁ + 3x₂ + MA₁ + MA₂ → min

Max бодлого

−M·A (сөрөг тэмдэг)

Ашгийг максимумчлах гэж байгаа тул A > 0 бол нийт ашиг −M·A-гаар асар ихээр буурна. Тиймээс алгоритм A-г 0 болгохыг эрмэлзэнэ.
Z = 40x₁ + 30x₂ − MA₁ → max

Товч дүрэм

M-ийн тэмдэг хамгийн их торгох чиглэлд байх ёстой — Min бодлогод торгууль «+M» (зардлыг өсгөнө), Max бодлогод торгууль «−M» (ашгийг бууруулна).

Бүлгийн хураангуй

Таван гол санаа

1Big-M бол шинэ алгоритм биш — симплекс + тусгай эхлэл. Алгоритмын логик хэвээр, зөвхөн гарааны хүснэгт байгуулах арга өөрчлөгдөнө.
2Гурван дүрэм: ≤ → +S (нэмэлт) · ≥ → −S ба +A (илүүдэл + зохиомол) · = → +A (зохиомол).
3+S = ашиглагдаагүй үлдэгдэл нөөц · −S = стандартаас давсан илүүдэл — хоёулаа эцсийн шийдэд гарвал хэвийн.
4M-ийн тэмдэг эсрэг: Min бодлогод +M·A (зардлыг өсгөнө), Max бодлогод −M·A (ашгийг бууруулна). M нь бусад бүх коэффициентээс хамаагүй том.
5Оновчтой шийдэд A = 0 байх ёстой. Хэрэв A > 0 үлдвэл бодлого шийдгүй (Infeasible).
